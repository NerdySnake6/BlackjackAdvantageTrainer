# Повторная проверка исправлений — бланк наблюдения

Одна копия на участника и устройство. Заполненные копии хранить вне Git.
Пустые поля означают отсутствие данных. Это качественная проверка исправлений;
недельные метрики Free-beta ведутся отдельно по FREE_BETA_RUNBOOK.md.

## Сборка и условия

- Код участника:
- Дата/время и часовой пояс:
- Commit / APK SHA-256 (из FEEDBACK_RETEST_BUILD.md):
- Модель телефона / Android:
- Язык EN/RU / масштаб текста / масштаб интерфейса:
- Установка: новая / обновление; прежняя версия и сохранённый прогресс:
- Опыт, выбранный в приложении:
- Наблюдение организованное / самостоятельное:

Для проверки beginner нужен участник с этим выбранным опытом. Не стирать
прогресс существующего участника ради сценария. Если условие недоступно,
отметить «не проверено» или использовать отдельное тестовое устройство.
Сначала повторить исходное затруднение, затем проверить крупный текст.
Организатор не объясняет термины до самостоятельной попытки; оказанную помощь
записывает. Не требовать правильного ответа для положительной оценки интерфейса.

## Отзыв участника

- Стало ли удобнее читать по сравнению с прежней сборкой? Что ещё мелко?
- Какие слова остались непонятными?
- Смог ли начать без объяснения организатора? Где понадобилась помощь?
- Что мешало продолжить?
- Автор исходного отзыва подтвердил исправление: да / нет / не участвовал.

## Ошибка и решение организатора

- ID сценария / код ошибки / важность P0–P3:
- Шаги воспроизведения:
- Ожидание / фактическое поведение:
- Обезличенный снимок (если предоставлен):
- Решение: кандидат для дальнейшего теста / требуется исправление / данных мало.

Блокирующий сбой установки, потеря прогресса или невозможность пройти действие
останавливают выдачу кандидата до разбора. Отсутствие проблемы на одном телефоне
не заменяет проверку остальных устройств и недельное наблюдение Free-beta.

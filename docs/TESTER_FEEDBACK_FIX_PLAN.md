# План исправлений по отзывам тестировщиков

Дата: 2026-10-02. Статус: план принят владельцем 2026-10-02; реализация идёт по шагам.
Отзыв относится к сборке, версия которой неизвестна; перед проверкой дать
тестировщикам текущий APK и записать build/устройство/OS. Имена и переписка
в репозиторий не включаются. Это качественный отзыв, не закрытие Free-beta gate.

Фраза о необходимости уменьшить шрифт — сарказм: предложение должно увеличивать
читаемость. Убирать ботов из всех сценариев нельзя считать очевидным следствием
отзыва: они дают дополнительные открытые карты для практики running count.
Полный пятибоксовый стол остаётся полезным продвинутому ученику.

## 1. Читаемость и обрезка стола — первый приоритет

- Разделить декоративную подложку и содержимое: овал/скругления могут остаться
  фоном, но не должны обрезать боксы, карты, подписи или элементы управления.
  На телефоне использовать более прямоугольную рабочую область и уменьшить
  декоративные отступы. Не менять правила, рандомизацию или движок раздачи.
- Убрать масштабирование целой руки вместе с текстом. Размер суммы и результата
  задаётся отдельно от геометрии карт; ориентир 14–16 logical px для основных
  подписей, с корректным системным text scaling. Это стартовые размеры для
  проверки на устройствах, не гарантированный универсальный минимум.
- Заменить широкую «веерную» руку на узкие перекрывающиеся карты с всегда
  видимым рангом и мастью. Последнюю карту показывать целиком; закрытая карта
  не раскрывает ранг/масть. Ориентир шага 25–30% ширины, но не меньше зоны
  индекса карты; длинная рука не должна уменьшать подписи или скрывать карты.
- Если пять мест не помещаются читабельно, дать активной руке увеличенную
  область, а остальным — компактные сводки. Открытые карты других мест остаются
  доступными для счёта, включая возможность раскрыть их без потери контекста.
  Не скрывать информационные карты при проверке RC.
- Показать все руки после Split: текущий seat.hands.take(2) не даёт увидеть
  третью/четвёртую руку. Использовать выбор руки/страницы с номером и состоянием,
  крупно показывать активную; первые решения и RC engine сохраняются.
- Итог раунда показывать крупно для игрока; подробности ботов могут открываться
  отдельно. Повышение читаемости не должно превращаться в пять длинных строк
  мелкого текста под каждой рукой.

Критерий: крайние места не обрезаны, ранг/масть каждой открытой карты доступны,
сумма и итог игрока читаются без увеличения изображения. Проверить EN/RU,
landscape с SafeArea, 2/4/8 карт, 1–4 split hands, hidden hole card и text 100/150/200%.
При недостатке площади использовать прокрутку/раскрытие, а не scaleDown.

## 2. Понятный вход для beginner

- До первого оцениваемого вопроса дать короткое объяснение: кто такой дилер,
  что считается рукой, цель сравнения сумм, значения карт, перебор и ничья.
  Затем отдельно объяснить натуральный blackjack и отличие от обычных 21.
  Не начинать с исключений после Split, пока смысл Split не введён.
- Добавить 2–3 наглядных действия без оценки: сложить две карты, увидеть
  результат добора, сравнить руку с дилером. Переиспользовать уже существующие
  FoundationScene и авторские демонстрации; не строить второй blackjack engine.
- Первое занятие beginner должно явно вести к основам. В Learn поднять вводный
  путь и текущий шаг; сложные группы и вызовы сделать второстепенными/сворачиваемыми.
  Опытный игрок сохраняет быстрый старт со стратегии. Table остаётся доступным.
- Вводный материал можно открыть повторно. Не требовать повторного tutorial
  у опытных игроков; не менять stable quick-start/skillId и уже сохранённые
  первые ответы/XP. Совместимость existing resume проверяется отдельно.

Критерий: человек без знания игры может объяснить цель, посчитать простую руку,
назвать перебор и понять первый вопрос без помощи разработчика. Проверка с
3–5 новичками оценивает понятность, отдельно от основной целевой Free-beta.

## 3. Объяснение терминов в месте использования

- Дать явные интерактивные термины: Hit, Stand, Double, Split, Surrender,
  hard/soft hand, RC. Использовать stable term keys и EN/RU определения,
  исходно из существующего glossary; при необходимости расширить его проверку.
- На телефоне нажатие открывает короткую карточку определения с одним примером
  и кнопкой закрытия. Не полагаться на hover/long press или маленький tooltip:
  способ доступа должен быть видимым. Семантическая метка и достаточная область
  нажатия обязательны.
- Не делать саму кнопку действия одновременно кнопкой справки: отдельный
  значок рядом предотвращает случайный Hit при попытке узнать значение.
- Не распознавать термины хрупким поиском слов по локализованным абзацам.
  Использовать явные связи copy/term key; определения не дублировать в виджетах.
- Не раскрывать ответ через справку во время самостоятельного checkpoint.
  Справка допустима в обучении, а её использование учитывается существующей
  политикой подсказок там, где она влияет на задачу.

Критерий: термин можно объяснить в контексте одним касанием, без ухода из урока
и без изменения ответа; EN/RU, screen reader, маленький экран, resume и feedback
работают. Checkpoint сохраняет отсутствие подсказок.

## 4. Учебный стол один на один — отдельный продуктовый выбор

Рекомендация: добавить явный preset «игрок и дилер» для изучения правил и
basic strategy; сохранить preset полного стола для совместной стратегии/RC.
В первом preset четыре места действительно Empty, а не невидимые Bot: иначе
будут появляться карты, которые ученик не видел. Использовать существующую
SeatConfiguration; не менять стандартный profile или пять engine slots.

Для этого preset возможен portrait layout: дилер сверху, крупная рука игрока,
действия снизу. Landscape полный стол сохраняется. Переключение preset только
в безопасной существующей границе раунда; UI объясняет, чем отличаются сценарии.
Активное решение и счёт не должны теряться при ориентации/переключении в фон.
Обычный preset новичка и автопереход orientation требуют отдельного решения
владельца и синхронизации PROJECT_CONTEXT/ARCHITECTURE/README.

Альтернатива меньшего объёма: только крупная активная рука в текущем landscape
столе, без нового preset. Она быстрее решает читаемость, но не закрывает жалобу
на обязательный поворот экрана. Полностью заменять стол одним боксом не предлагается.

## Порядок реализации и проверки

1. Исправить обрезку, масштабирование и длинные/split руки; сохранить механику.
2. Упростить первый материал и порядок Learn для beginner.
3. Добавить доступную справку терминов.
4. После выбора владельцем — preset игрок/дилер и portrait вариант.
5. Выдать тестировщикам один зафиксированный APK, повторить конкретные сценарии
   из отзывов на тех же устройствах, записать build и фактические результаты.

Каждый шаг — отдельный commit/push после format, analyze и flutter test.
Для UI/runtime — Android build; для orientation/shared lifecycle изменений —
также iOS build. Математические правила не меняются; при изменении обучающих
примеров сверить их с существующей независимой reference fixture. Дать доступ
к наблюдениям по устройствам в Free-beta протоколе, но не объявлять layout-тесты
доказательством улучшения обучения или закрытием пользовательского gate.

Готовность: исходный автор отзыва повторяет сценарии и подтверждает читаемость;
новички проходят первый вопрос без объяснения терминов организатором; отсутствуют
обрезка, потеря состояния, скрытые открытые карты и блокирующие P0/P1. Реальные
результаты пока не получены, оценки трудозатрат уточняются после prototype layout.

сравнение 17/18, перебор 24, исходный A+K. Вначале объясняются дилер, рука,

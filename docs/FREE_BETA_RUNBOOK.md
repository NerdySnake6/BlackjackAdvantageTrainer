## Проверяемый объём

Free содержит 25 игровых уроков и отдельный basic-strategy checkpoint:
4 вводных, 11 strategy + checkpoint, 4 Math & Reality, 6 Hi-Lo/RC.
Узел `basic-strategy-checkpoint` открывает существующую проверку из двух
непересекающихся форм по 100 задач. Совместимый ключ сохранения остаётся
`mixed-basic-strategy`; XP и прежние результаты не пересчитываются.
Недельный совместный вызов — дополнительная повторяемая практика, не 27-й
урок и не сертификат. Игровые independent-задачи нельзя использовать как
новые pre/post/delayed измерения. Held-out банки нельзя раскрывать заранее.

## До набора группы

1. Зафиксировать commit SHA, app version/build, дату, APK SHA-256, Android API
   и EN/RU пакет для кандидата. Сборка и установка — по [BETA_RELEASE.md](BETA_RELEASE.md).
   Debug APK для разработчика не означает разрешение публичного выпуска.
2. Выполнить format, analyze, полный coverage test, content validation,
   Android build и проверки подписи/разрешений кандидата. Проверить CI.
3. На физическом Android выполнить smoke: новая установка, onboarding,
   обучение, ошибка и исправление, RU/EN, закрытие процесса и resume,
   переключение в фон, обновление поверх прошлой версии без потери прогресса.
   Указать устройство/OS, build, результат, issue ID и обезличенное доказательство.
4. Проверить малый экран и крупный текст, доступность всех кнопок, отсутствие
   блокирующих P0/P1. Эмулятор и widget tests не заменяют физический Android.
5. Подготовить заранее проверенные эквивалентные внешние задания и неизменный
   порядок измерений. Независимый проверяющий хранит ответы вне Git. Не
   переписывать наборы после знакомства с результатами участников.

## Подготовка организатора

Передать участникам [памятку](FREE_BETA_PARTICIPANT_GUIDE.md), проверенную
сборку и инструкцию установки. До первого визита пояснить срок хранения,
способ отзыва согласия и доступ к исследовательским записям. Контакты для
визитов добавляются организатором вне Git. Зафиксировать визиты относительно
реального первого занятия; общий календарь нельзя считать одинаковым D7
для всей группы. Длительность первого визита — ориентировочно 20–30 минут,
follow-up — 5–10 минут; фактическую длительность записать отдельно.

Журнал: started_at_utc — ISO 8601 с Z; local_day_index — целое 0–7 по местной
календарной дате участника; locale — en/ru; visit_type — spontaneous/organized;
session_type — baseline/training/post/delayed/follow_up; булевы поля — true/false
или пусто. Accuracy — процент 0–100, пустое значение не превращать в ноль.
Session_code уникален внутри participant_code; одну сессию не считать дважды.
Для learning_activity=true должно быть фактическое учебное действие, а не
просто запуск приложения. Один исследовательский визит может включать
несколько этапов, но не считается несколькими учебными сессиями ради метрики.

## Группа и наблюдение

Набрать 30–50 взрослых целевых участников, знающих правила и интересующихся
обучением advantage play. Участие добровольное; согласие на исследование
отдельно от analytics/crash opt-in. Telemetry остаётся выключенной без согласия;
новых событий в этой итерации нет. Участники без telemetry могут добровольно
сообщать занятия и проходить согласованные наблюдаемые проверки.

Контакты, согласия, сырые ответы и записи экрана хранятся вне репозитория.
Приглашения не отправляются без разрешения владельца. Для обезличенного журнала
использовать [FREE_BETA_SESSIONS.csv](FREE_BETA_SESSIONS.csv): одна строка на
реальное занятие, постоянный participant_code, UTC timestamp, local_day_index
от даты первого занятия, build, locale, spontaneous/organized visit и результат.
Пустое поле — отсутствие измерения. Не заполнять журнал синтетическими людьми.

Зафиксировать состав основной группы до начала анализа. Не заменять ушедших
участников успешными и не исключать неудобные результаты. Незавершённое первое
занятие учитывается в знаменателе завершения. Для D7 дождаться седьмого дня
каждого участника; до этого показатель недоступен. Самостоятельные и
организованные возвращения считать отдельно. Если активность участника
неизвестна (например, он не передал добровольный дневник), показать missing
и границы возможного результата, а не считать отсутствие данных отсутствием
занятий. Не объявлять gate пройденным при неполном наблюдении.

## Недельная практика

Первый визит: baseline на новых внешних заданиях, один урок и post-check.
Участник выбирает последующие темы и частоту занятий. План Learn предлагает
повторение, следующий урок и необязательный вызов. Не напоминать всей группе
каждый день: такие визиты искажают самостоятельное возвращение и отмечаются
organized. Через 48–72 часа — delayed-check; на седьмой день — сбор дневника
и причин продолжения/ухода. Не превращать XP или результаты повторяемого
недельного набора в доказательство прироста на новых заданиях.

Наблюдатель фиксирует обращения за помощью, затруднения, прекращение занятия,
ошибки сохранения и layout, а не угадывает мотивацию. Для критической ошибки
остановить выдачу кандидата, сохранить обезличенные сведения, исправить,
прогнать регрессии и зафиксировать новый build. Данные разных builds отделить.

## Отчёт и решение

| Метрика | Расчёт | Порог | Текущий результат |
| --- | --- | --- | --- |
| Первый урок | Участники, завершившие первый урок / вся основная группа | ≥60% | Нет данных |
| Пять занятий за первую неделю | Участники с ≥5 фактическими учебными сессиями в дни 0–6 / группа | ≥25% | Нет данных |
| Самостоятельный D7 | Участники с spontaneous учебной активностью в local day 7 / группа с полным окном | ≥15% | Нет данных |
| Организованный D7 | Та же формула, visit_type=organized | Диагностика отдельно | Нет данных |
| Обучение | Парные pre/post/delayed результаты новых заданий; first answers, hints, пропуски | Отдельно от XP | Нет данных |
| Уход | Число, момент и добровольно сообщённая причина; missing отдельно | Без догадок | Нет данных |
| Устройства | Реальные модели/OS, установка, обновление, lifecycle, accessibility | Нет блокирующих P0/P1 | Не проверено |

Отчёт перечисляет знаменатели, пропуски, builds, помощь и различия organized/
spontaneous. При завершении первого урока <40% или возвращении к третьему
занятию <15% пересмотреть направление и onboarding. При промежуточных
результатах зафиксировать решение владельца и следующую проверяемую гипотезу.
Успешные тесты приложения не закрывают этот gate. Переход к Pro требует
отдельного решения после фактических данных Free-beta и проверки интереса.

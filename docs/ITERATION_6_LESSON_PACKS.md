# Контентные пакеты итерации 6

Этот документ фиксирует учебный blueprint для трёх первых игровых уроков. Он
подготовлен до UI-анимаций и не заменяет production-каталог: стабильные IDs
берутся из `COURSE_SKILL_MAP.json`, а математика проверяется отдельно в
`test/fixtures/iteration6_lesson_pack_reference.json`.

Профиль всех примеров: `standard_6d_s17_das_ls_peek_3to2`. В пакетах нет
composition-dependent deviations, ставок или обещаний результата; задача —
объяснить признак решения и проверить перенос на новый порядок карт.

## Общий шаблон урока

Каждый пакет содержит пять последовательных блоков:

1. **Theory / Теория** — одно правило и граница применимости.
2. **Worked example / Разобранный пример** — карты, открытая карта дилера,
   ожидаемое действие и короткое «почему».
3. **Misconceptions / Ошибки** — неверный ответ и корректирующее объяснение.
4. **Guided practice / Практика с направлением** — 2–4 задачи с видимым
   признаком; подсказка не засчитывается как самостоятельный ответ.
5. **Independent test / Независимая проверка** — новые представления без
   названия семейства руки и без повторения anchor example.

В production UI эти поля будут локализованы через EN/RU content assets. Этот
blueprint намеренно хранит текст отдельно от виджетов, чтобы будущие анимации
не содержали собственных правил.

## `hard-12` / `strategy.hard_12`

**Theory / Теория.** RU: «Жёсткие 12 — граница: Stand против 4–6 дилера,
иначе Hit». EN: “Hard 12 is a boundary: stand against dealer 4–6, otherwise
hit.” Карта дилера определяет риск; одинаковые 12 не получают один ответ.

**Worked example / Пример.** `10+2` против `3` → Hit: дилерская 3 не входит в
границу Stand. `10+2` против `4` → Stand: 4–6 — слабые upcard.

**Misconceptions / Ошибки.**

- «На 12 всегда нужно брать карту» → сначала проверить диапазон 4–6.
- «Любая маленькая карта дилера слаба» → 2 и 3 остаются Hit для hard 12.

**Guided practice / Практика.** Чередовать `10+2` и эквивалентные пары (`9+3`,
`8+4`) против 2, 4, 6 и 7; после ответа показывать только диапазон дилера и
сумму, но не название следующего правила.

**Independent test / Проверка.** Десять новых задач со всеми dealer upcard
`2,3,4,5,6,7,8,9,10,A`; ожидаемые действия и независимый источник записаны в
fixture. Проход — 8/10 без подсказки, затем обязательный перенос на другую
композицию того же hard total.

## `soft-18` / `strategy.soft_18`

**Theory / Теория.** RU: «Soft 18 — не всегда Stand: Double против 3–6 на
первых двух картах, Stand против 2, 7, 8, Hit против 9, 10, A. Если Double
недоступен, против 3–6 используется Stand». EN: “Soft 18 is not always a
stand: double 3–6 on the initial two cards, stand 2/7/8, hit 9/10/A; when
double is unavailable against 3–6, stand.”

**Worked example / Пример.** `A+7` против `6` → Double при доступном действии.
`A+2+5` против `6` → Stand: тот же soft 18, но Double уже недоступен после
третьей карты. `A+7` против `9` → Hit.

**Misconceptions / Ошибки.**

- «Soft 18 всегда Stand» → против 3–6 сначала проверяется Double.
- «Недоступный Double всегда превращается в Hit» → soft 18 имеет Stand
  fallback против 3–6.
- «Три карты не могут быть soft» → `A+2+5` сохраняет soft 18.

**Guided practice / Практика.** Две пары представлений (`A+7` и `A+2+5`)
перемешиваются с dealer 3, 6, 8 и 9. UI отдельно показывает legal actions,
чтобы обучаемый увидел причину fallback, а не воспринял её как исключение.

**Independent test / Проверка.** Полная строка dealer upcard и четыре fallback
сценария без Double зафиксированы в fixture. Ни один ожидаемый ответ не
вычисляется генератором production-кода.

## `hi-lo-cancellation` / `counting.cancellation`

**Theory / Теория.** RU: «Low-карта 2–6 даёт +1, high-карта 10–A даёт −1;
пара +1/−1 взаимно компенсируется. 7–9 имеют 0». EN: “A low card (2–6) is
 +1, a high card (10–A) is −1, and a +1/−1 pair cancels; 7–9 are zero.”

**Worked example / Пример.** `5, K` можно увидеть как одну нулевую группу;
добавление `8` не меняет running count. `2, 4, Q, A` также даёт 0 одним
chunk’ом.

**Misconceptions / Ошибки.**

- «Каждую карту нужно проговаривать отдельно» → сначала замечать пары low/high.
- «Нейтральная пара — это одинаковые ranks» → компенсация определяется tags,
  а не названием карты.
- «Туз имеет tag 0, потому что стоит 1 или 11 очков» → Hi-Lo tag независим от
  blackjack value; туз получает −1.

**Guided practice / Практика.** Показывать короткие группы из 2–5 открытых карт,
сначала с одной очевидной парой, затем с нулевыми 7–9 и разным порядком. После
ответа раскрывать tag каждой карты и итог группы.

**Independent test / Проверка.** Пять новых последовательностей с ожидаемыми
tags и running count проверяются независимой таблицей rank→tag. Порядок карт
меняется, а часть нулевых карт добавляется как отвлекающий материал.

## Источники и границы доказательства

- Basic-strategy решения сверены с транскрибированной fixture
  `standard_strategy_s17_das_ls.json` и источниками, перечисленными в
  `STRATEGY_VALIDATION.md`.
- Ограничение soft 18 при недоступном Double защищено
  `standard_strategy_action_constraints.json` и тестами итерации 2–3.
- Hi-Lo tag — стандартная сбалансированная шкала `+1/0/−1`; независимые
  ожидаемые значения находятся в fixture итерации 6.

Новые rule profiles, index deviations, composition-dependent решения и
производственные lesson IDs, которых ещё нет в каталоге, этим пакетом не
активируются.

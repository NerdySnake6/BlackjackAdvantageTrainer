Статус на 2026-09-05: владелец подтвердил, что участников ещё нет, и попросил

Техническая работа продолжается с итерации 11. Этот файл
описывает одинаковое проведение сессий и расчёт решения. Он не создаёт

## До первой сессии

Проверенный код уроков — коммит `85cfda3`. Обычный debug APK доступен в
Artifacts [успешной сборки GitHub Actions](https://github.com/NerdySnake6/BlackjackAdvantageTrainer/actions/runs/33967564860);
при истечении срока хранения собери `flutter build apk --debug` из этого
коммита. Для набора фиксируй SHA коммита вместе с версией приложения:
одного номера версии недостаточно для различения сборок.

1. Набрать восемь совершеннолетних добровольцев по screening из
   [PILOT_RECRUITMENT.md](PILOT_RECRUITMENT.md). Один участник получает только
   обезличенный код `P-001` … `P-008`; соответствие кода контакту хранится вне
   репозитория.
2. Зафиксировать build, locale и устройство. Имя, email, телефон, рекламный
   ID, свободный user ID и переписка в журнал не попадают.
3. Получить отдельные research / analytics / crash consent. Любой telemetry
   opt-in остаётся добровольным и не является условием участия.
4. Подготовить три набора задач: `pre`, `post` и `delayed`. Post и delayed
   используют новые эквивалентные состояния, а не копию задач приложения.
   Проверяющий хранит ключ ответов вне Git.

## Одна сессия

Используй одну строку в `PILOT_FEEDBACK_LOG.csv` на каждый этап:
`session_type=pre`, `training`, `post`, `delayed`.
В первый визит получаются три отдельные строки, во второй — одна.
Один `participant_code` связывает все этапы участника; `cohort=pilot`.
`session_number` — номер визита (1 или 2), а не номер задания.
Так результаты до и после обучения не перезапишут друг друга.

1. Напомнить границу: это автономная учебная симуляция, не подсказка для
   реального стола и не обещание прибыли.
2. Провести pre-test без подсказок и без объяснения ответов. Записать accuracy,
   медианное время и пропуски.
3. Дать участнику открыть APK самостоятельно. Наблюдатель не ведёт мышь,
   телефон или ответы; вопросы участника фиксируются как `help_requests`.
4. Дать три пилотных урока, включая их теорию. Не подсказывать правильное действие;
   можно только повторить текст интерфейса или safety boundary.
5. Сразу провести post-test на новых эквивалентных задачах. Затем показать
   существующий MCQ-формат и задать одинаковые вопросы: что было понятно,
   где возникла пауза, какой формат предпочитает. Сравнительный просмотр
   проводится после post-test; его порядок одинаков у всех участников и
   фиксируется как ограничение исследования.
6. Через 48–72 часа провести delayed-test без подсказок и записать дату,
   accuracy и причину отсутствия, если визит пропущен.

Наблюдатель отмечает фактические события, а не интерпретации: место остановки,
непонятный термин, повторное нажатие, ошибка сохранения, overflow, просьба о
подсказке. Свободная заметка перед занесением в CSV обезличивается и не содержит
текстов ответов или последовательностей карт.

Для каждого набора заранее зафиксируй ID, версию, число задач, разрешённые
действия и проверенные ответы во внешнем протоколе. Используй одинаковое
число задач и распределение навыков на всех трёх этапах. Зафиксируй соответствие
этапа набору до начала первого участника; между участниками наборы не меняются.
`first_answer_accuracy` записывается в процентах 0–100, а не долей 0–1.
Неотвеченная задача законченного теста входит в знаменатель как неверная;
прерванный тест получает `completed=false` и не участвует в парном расчёте.
Пустое значение означает отсутствие данных, а не ноль.

В строке `training` поле `completed=true` означает, что участник закончил
все три урока. `help_requests` считает обращения за помощью; фактическая
помощь наблюдателя с интерфейсом или задачей, в том числе без просьбы,
отмечается в `redacted_note` как `assisted=true`. При отсутствии помощи
указывается `assisted=false`. Ответы встроенного Тренера учитываются через
`hints_used` и не считаются помощью разработчика.
`format_preference` в строке `post`: `new`, `old`, `equal` или пусто
при отказе отвечать. Время delayed-визита отсчитывается от окончания обучения;
проверка вне окна 48–72 часа отмечается во внешнем протоколе отдельно.

## Расчёт gate

После восьми кодов собрать отдельную таблицу анализа вне репозитория:

- `completed_three_lessons`: минимум 6 из 8 без помощи разработчика;
- `format_preference`: минимум 5 из 8 выбирают новый формат после знакомства с
  обоими вариантами;
- для участников с pre-accuracy ниже 85%: медианный post-прирост не менее
  15 процентных пунктов и delayed-прирост не менее 10;
- если подходящих участников для прироста меньше пяти, набор расширяется;
- участников с pre-accuracy от 85% анализировать отдельно по сохранению
  точности, времени и новой ценности.

Сначала для каждого участника рассчитай `post − pre` и `delayed − pre`
в процентных пунктах, затем медиану индивидуальных разностей. Разность двух
групповых медиан не используется. Для обеих метрик нужна одна группа минимум
из пяти участников с pre ниже 85% и полными тремя проверками; недостающие
delayed-данные не позволяют объявить gate пройденным. Отдельно укажи количество
пропусков и причины, если они известны.

Первые восемь подходящих и давших согласие участников заранее образуют
основную группу для порогов 6/8 и 5/8. После начала исследования их не заменяют
по результатам или причине ухода. Дополнительный набор для группы прироста
не меняет этот знаменатель. В текущем состоянии решение — `pending`:
реальных наблюдений нет.

При достаточных данных решение фиксируется как `continue`, `iterate` или
`stop`; до этого — `pending`. Нельзя считать
пропущенный визит отрицательным отзывом, добавлять синтетические строки или
выдавать unit/widget/integration tests за результат обучения.

## Безопасность и остановка

Сессию немедленно остановить при запросе live-table input, overlay,
распознавании карт, wagering или обходе наблюдения казино. P0/P1 дефект,
который мешает сохранить результат, блокирует передачу APK следующему
участнику до исправления и повторного smoke-теста.

После пилота обновляются только обезличенный CSV, журнал дефектов и этот отчёт.
Контакты, формы согласия и сырые заметки остаются во внешнем защищённом
хранилище владельца.

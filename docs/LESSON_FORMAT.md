# Формат игровых уроков Learn

Итерация 12, 2026-09-06. Формат описывает авторские задания для двух уже
реализованных сцен. Он не генерирует новые математические состояния и не
заменяет старый MCQ-каталог или Quick Review.

## Версии и идентификаторы

- `schemaVersion: 1` — версия структуры игрового JSON, обязательна в каждом уроке.
- `version` — версия содержания и поведения конкретного урока для resume.
  При изменении порядка, ответов, этапов или оценки её нужно увеличить.
- `id`, `skillId`, `theory.id`, `scenarios[].id` — стабильные, независимые от языка
  ключи. Перевод меняет текст, но не эти ключи или математические состояния.
- `profileId` — точный проверенный профиль. Сейчас разрешён только
  `standard_6d_s17_das_ls_peek_3to2`; поле не разрешает новые профили автоматически.

При переносе трёх уроков их `version: 1` сохранена: тексты, порядок, карты,
ответы, этапы и оценка совпадают с коммитом `40906cf`. Схема сохранения
`DecisionLessonSession` не менялась. Старый прогресс не сбрасывается.

## Обязательные блоки

| Поле | Смысл |
| --- | --- |
| `title`, `subtitle` | Локализованные подписи урока. |
| `theory: {id, text}` | Авторское объяснение до первого задания. |
| `scoring` | Версионированная политика первых ответов. |
| `scenarios` | Упорядоченные миссии на общих сценах. |

`scoring` содержит `policyId: "first_answer_v1"`, `passCorrect: 8`,
`starCorrect: [8, 9, 10]`, `topStarRequiresUnassisted: true`.
Это проверяемый контракт обычного урока, не произвольно настраиваемая экономика.
Неподдержанная политика отклоняется. XP остаётся в совместимом адаптере AppState.

Каждая миссия содержит:

- `kind`: `decision` или `runningCount`;
- `stage`: `introduction`, `practice` или `independent`;
- `cards`: последовательность rank labels; для решения — `dealer` и `actions`,
  для счёта — `initialCount`;
- `expected`: правильное действие или целое число строкой;
- `coaching: {explanation, contrast, mistakes}`: объяснение правильного действия,
  контрастный пример и разбор предусмотренных ошибок. Для счёта ключ ошибки
  `count`, для решения — имя действия.

Порядок: 2–4 вводных задания, пять тренировочных и пять самостоятельных.
Вводные не оцениваются; в самостоятельных запрещены подсказки. Оценка,
номер задания, доступность подсказки и конец сессии вычисляются из содержимого,
а не из номера конкретного урока или фиксированного индекса 11.

Самостоятельные пять заданий остаются практикой. Порог прохождения урока —
80% первых ответов во всех десяти оцениваемых задачах. Отдельная проверка
`MasteryCheckSession` использует новые ситуации, минимум 9/10, без подсказок,
таймера и промежуточного разбора. После завершения доступны ответы и теория.
Банк v1 содержит два непересекающихся варианта на урок, защищённых reference
тестами. Soft 18 проверяет многокарточные руки без Double. Это не полный
сертификат навыка. Каждый ответ сохраняется в `ProgressSnapshot.masteryChecks`
вместе с вариантом и подписью; раскрытый вариант нельзя пройти заново ради
значка. После исчерпания новых вариантов остаётся обычная практика без лимита.

Доменная сессия остаётся pure Dart. Presentation выбирает одну из двух сцен
по типу миссии. Совместимые getters `theory`, `explanation`, `contrast`,
`mistakes` оставлены для существующих потребителей.

## Проверки

`lesson_format_test.dart` проверяет структуру, пороги, неизменяемые коллекции,
тот же runtime с четырьмя вводными заданиями, отказ от неизвестной политики
и восстановление сохранения до переноса формата. `pilot_content_test.dart`
по-прежнему сравнивает математические ответы с независимой fixture итерации 6.

## Проверка пакетов (итерация 13)

Из корня репозитория перед сборкой:

```sh
dart run tool/validate_content.dart
```

Та же pure-Dart проверка запускается при загрузке пакета в `ContentRepository`.
Отсутствующий locale package по-прежнему использует English fallback, но
существующий испорченный пакет не скрывается подменой языка.

Проверяются manifest и ссылки на локальные файлы, совпадение contentVersion,
единственный разрешённый profile, непустые theory/coaching/glossary, уникальные
ID во всём пакете и наличие разбора каждого доступного ответа. Неизвестные
ключи ошибок отклоняются; пояснения известных, но недоступных в текущей руке
действий допустимы. Проверяется согласованность итогового Hi-Lo и отсутствие
двухкарточных действий в многокарточной руке.

Команда CI дополнительно сверяет lesson/skill ссылки с утверждённой картой
и EN/RU семантику: ID, версии, этапы, типы, карты, действия, ответы и оценку.
Тексты могут различаться. Полнота ключей ARB защищена отдельным тестом.
URL источников проверяются синтаксически, без сетевого запроса; это не проверка
содержимого источника. Независимые математические fixtures остаются обязательными.

## Сохранения и миграция (итерация 14)

Новые сессии используют `schema: 2` и `contentSignature`: детерминированное
описание нелокализуемой структуры урока (не криптографическая подпись).
Это та же структура, которую сравнивает EN/RU validator. Изменение карт,
действий, этапов, порядка, профиля или оценки без обновления версии теперь
также выявляется при resume; изменение текста перевода не сбрасывает сессию.

При старте `PilotProgressMigration` переносит совместимые сессии schema 1
в schema 2 одним сохранением снимка. Фаза, порядок, первый ответ, подсказки,
раскрытые карты, черновой счёт и уже записанная награда не меняются.
Сохранённая schema 2 служит отметкой выполненного переноса: повторный запуск
не пишет тот же снимок и не вызывает XP-адаптер.

Ошибка записи оставляет исходный снимок; миграция повторяется при следующем
старте. Старые совместимые сессии остаются читаемыми и могут сохраняться в новом
формате при обычном действии. Неизвестные и повреждённые сессии сохраняются
для существующего явного перезапуска конкретного урока. Общего сброса нет:
XP, streak, язык, experience, consent и legacy scores/sessions/review не меняются.
Язык каталога при старте выбирается сначала из сохранённой настройки, затем из ОС.
